# Infographic Design Principles

## 1. Story before decoration
The infographic must have one visual thesis. Every module must either orient, explain, enable action, provide evidence, or set a boundary.

## 2. Hero hierarchy
Use one dominant hero object or visual metaphor. Supporting modules are satellites, not equal-weight cards. Judge the silhouette at thumbnail size before polishing details.

## 3. Beginner-first translation
For introductory content, organize around user questions rather than the source document's chapter order. Prefer: what → value → prerequisites → install → first use → workflow → outputs → FAQ/next step.

## 4. Respectful language
Do not label audiences with terms that can feel dismissive or patronizing. Prefer neutral learning-stage labels such as 入门指南, 快速开始, 第一次使用, 基础教程.

## 5. Claim discipline
Every factual number, command, requirement, benchmark, product status, or limitation must be traceable to a source or explicitly marked as inference in planning. Never decorate uncertainty into certainty.

## 6. Copy restraint
Use real text where the eye lands. Reduce secondary copy before reducing font size. Do not repeat the same claim in title, card, caption, and footer.

## 7. Flow over inventory
When information has causality or sequence, use a visual path. Avoid turning a process into a uniform inventory of boxes.

## 8. Song-handdrawn profile
Default visual language for Fei-branded explainers:
- warm paper ground;
- ink linework;
- celadon, sage, gray-green, mist-white accents;
- restrained watercolor texture;
- generous negative space;
- botanical/mountain motifs used as atmosphere, not content substitutes;
- warm yellow reserved for a small number of action/warning accents.

## 9. Technical recognizability
Terminal, code, browser, phone, diagram, chart, and product UI should remain semantically recognizable even when rendered in a hand-drawn style.

## 10. QA is part of design
Check factual fidelity, hierarchy, mobile readability, text clipping, duplication, command accuracy, and tone after rendering. A renderer's successful output is not approval.
