# Profile: technical-architecture

Use for system architecture, agent workflows, software components, APIs and technical mechanism explainers.

## Information order
1. One-sentence system purpose
2. Core actors/components
3. Primary data/control flow
4. Key state transitions
5. Interfaces / boundaries
6. Constraints / failure modes
7. Optional implementation notes

## Composition
One architecture hero occupies the center. Use connectors and spatial grouping rather than a card inventory. Keep one dominant flow direction.

## Evidence
Distinguish literal architecture from schematic simplification. Label illustrative relationships when the source does not specify exact topology, scale or performance.

## Copy rule
Prefer nouns on nodes and verbs on connectors. Keep protocol names, commands, ports, versions and API identifiers exact when verified.
